## 2. ランタイム設定 `/config.json`

ビルド成果物に環境値を埋め込まず、CloudFront から配信する `/config.json` を起動時に読む（`src/lib/config.ts` の `RuntimeConfigSchema`）。Infra 側はこの形で生成すること。

```json
{
  "region": "ap-northeast-1",
  "userPoolId": "ap-northeast-1_XXXXXXXXX",
  "userPoolClientId": "xxxxxxxxxxxxxxxxxxxxxxxxxx",
  "oauth": {
    "domain": "xxxx.auth.ap-northeast-1.amazoncognito.com",
    "redirectSignIn": "https://xxxx.cloudfront.net/login",
    "redirectSignOut": "https://xxxx.cloudfront.net/login",
    "oktaProviderName": "Okta"
  }
}
```

- `oauth` は任意。無い場合「Oktaでログイン」ボタンは無効表示になる。
- `region` は IVS Chat の接続先にも使う。秘密情報は含めない（いずれも公開値）。

## 3. 認証とガード

| 状態 | 遷移 | 例 |
| --- | --- | --- |
| 未ログイン | `/login` | 視聴者が `/watch` を直接開く → `/login` |
| 表示名未設定 | `/display-name` | 初回ログイン直後 |
| ロール不許可 | その場で「権限がありません」+ ホームへ | 視聴者が `/admin/users` → 案内、ホーム `/watch` |
| `/` | ロール別ホーム（F-AUTH-08） | camera → `/send/camera`、admin → `/watch`（スイッチングへのリンク表示） |

- ログイン成功後は毎回 `/display-name`（前回値を初期表示, F-NAME-01）→ 決定でロール別ホームへ。
- 初回ログイン（Cognito `NEW_PASSWORD_REQUIRED`）は `/password` の「初回パスワード設定」へ。パスワード方針: 12文字以上・英大文字/小文字/数字。
- トークン更新: `fetchAuthSession()` が期限切れ時に自動更新。API が `401 TOKEN_REFRESH_REQUIRED`（グループ未反映）を返したら `fetchAuthSession({ forceRefresh: true })` で取り直して1回だけ再送。再送後も 401 ならログイン画面へ戻す（無効化ユーザーは次回更新で利用不可, F-AUTH-07）。
- 表示名・コメントは React の通常描画のみ（`dangerouslySetInnerHTML` 不使用）。テスト `CommentPanel.test.tsx` で `<img onerror>` が文字列表示されることを確認。

## 4. 視聴（U-01）とコメント

- `GET /api/broadcast` の `status === 'live'` の間だけ `useViewerStage(true)` で配信用ステージ（`stage === 'broadcast'` のトークン）を SUBSCRIBE。`idle`/`ended` は待機画面（F-VIEW-02）。
- 切断（`ERRORED`/`DISCONNECTED`）時はトークンを再発行して再参加。待ち時間は 1s→2s→4s…最大30s（`backoffMs`）。
- 自動再生制限のため最初はミュート再生し、「タップして音声オン」を表示。音量スライダー・ミュート・全画面（iOS は `webkitEnterFullscreen`）。
- Chat はログイン中 1 タブ 1 接続（`AppLayout` 内の `ChatProvider`）。カスタムイベントで React Query を再取得:
  - `broadcast-started` → broadcast / `broadcast-ended` → broadcast, archives / `slides-updated` → slides / `archives-updated` → archives
- コメント送信: クライアント側でも shared の `CommentSchema`（前後空白除去後 1〜200文字・制御文字不可）と 3秒に1回を検証。表示名はメッセージ属性として送らない（審査 Lambda が PROFILE の表示名で上書きし、表示はその値かトークン由来の送信者属性のみ。Review-1 R1-04）。例: 201文字 →「200文字以内で入力してください」、1秒後の連投 →「連投はできません。2秒後に送信できます」。
- 停止中ユーザー（`me.commentSuspended` または Chat トークンに `SEND_MESSAGE` なし）は送信欄を無効化し理由を表示。管理者が停止すると `serverDisconnect` を受けて `/api/me` を再取得し、再接続後のトークンにも反映される。
- 管理者の同時視聴者数（F-VIEW-05）は視聴画面にのみ表示（15秒ごと）。

### スイッチング画面（Web-B）からの再利用

```tsx
import { CommentPanel, useAdminModeration } from '@/features/viewer/CommentPanel';

function SwitcherCommentPanel() {
  // AppLayout 配下なので ChatProvider の接続を共有する
  return <CommentPanel className="h-96" moderation={useAdminModeration()} />;
}
```

`moderation` は `{ onDelete(comment), onSuspend(comment) }`。独自の処理を差し込みたい場合は同じ型のオブジェクトを渡す。

## 5. スライド・アーカイブ

- U-02: `POST /api/files/cookies` 成功後に一覧を表示。閲覧はダイアログ内 `iframe`（新しいタブで開くリンク併記）、ダウンロードは `<a download>`。Cookie は表示中 50 分ごとに再取得。
- U-04: 再生前に `POST /api/archives/{id}/cookies` で当該アーカイブだけに効く Cookie を取得（非公開は admin 以外 403。R1-08）。再生 URL は API の `playbackPath` をそのまま使用（組み立てない）。Safari はネイティブ HLS、それ以外は hls.js（`withCredentials`）。`controlsList="nodownload noremoteplayback"`・`disablePictureInPicture`・右クリック抑止。
- 管理者は一覧で公開スイッチ・タイトル変更（1〜100文字）・保存期限の表示と延長（日付入力。現在の期限より後の日の 23:59:59 JST を `retainUntil` として PATCH。例: 2028-03-31 → `2028-03-31T14:59:59.000Z`。R1-22）・削除（確認ダイアログ）。

## 6. 管理画面

- A-02: クライアント検証（拡張子 `.pdf`・MIME `application/pdf`・1B〜50MB）→ `POST /api/slides/upload-url`（`slideId,url,fields`）→ S3 へ presigned POST（認証ヘッダーなし）→ `POST /api/slides/{slideId}/complete`。並べ替えは上下ボタン（Tab で到達・Enter/Space で操作）、楽観的更新し失敗時は元に戻す。
- A-04: コメント一覧は U-01 の `CommentPanel` にモデレーションを差し込んで再利用。停止中ユーザー一覧（`GET /api/users` の `commentSuspended`）から解除。NGワードの追加（1〜100文字・重複チェック）/削除。CSV 出力は Blob のまま保存して UTF-8 BOM を保持（例: `comments-20261019.csv`）。
- A-05: 招待はテキスト（改行・カンマ・空白・セミコロン区切り）と CSV 読み込み（見出しに `email`/`メールアドレス` 列があればその列、無ければ1列目）。形式エラーがあれば送信しない。100件超は 100 件ずつ分割送信。応答の部分成功（`invited` / `failed[{email,reason}]`）を表示し、失敗したアドレスだけを入力欄に残す。途中のバッチが失敗してもそれまでの成功分は表示する（R1-11）。自分自身の行はロール変更・無効化・削除を無効化（管理者の締め出し防止）。

## 7. UI 方針の適用

- shadcn/ui の組み合わせのみ（不足分の `badge`/`alert` は shadcn の原典をそのまま追加）。アイコンは lucide-react のみ。
- 色は `index.css` のトークンのみ。アクセント（`primary`）は主要アクション（ログイン・決定・アップロード等）と LIVE バッジのみ。破壊的操作は `destructive`。任意色クラスの直書きなし（grep で確認）。
- タップ領域: アイコンボタンは `size-11`（44px）、テキストボタンは `min-h-11`。スマホではサイドバーがシートになる。
- ダークモード: `next-themes` で OS 設定に追従。`prefers-reduced-motion` は既存 CSS とスピナーの `motion-reduce:animate-none` で尊重。

## 9. ミューテーションテスト（Stryker）

- 設定: `apps/web/stryker.core.config.json`（mutate: `src/lib/**`（`ivs`・テスト・`utils.ts`・`query-keys.ts` 除く）、`features/auth/guard.ts`、`features/auth/password-schemas.ts`、`features/viewer/send-block.ts`、`features/{slides,archives}/api.ts`、`features/admin/*-api.ts`。閾値 break 80）。`package.json` の `mutation` は `stryker run stryker.core.config.json && stryker run stryker.media.config.json`。
- **スコア: 未計測。** 作業環境のサンドボックスがローカルポートの listen を禁止しており、Stryker core の logging server 起動時に `listen EPERM: operation not permitted 0.0.0.0` で終了した。coordinator の指示により計測は後続タスクで行う。
- 生存変異体: 未計測のため記録なし。計測時に確認すべき等価変異の候補（予測であり実測ではない）:
  - `lib/retry.ts` の `Math.min(…, 30_000)` 境界と `lib/files.ts` の `COOKIE_REFRESH_MS` 比較 `<` → `<=`（テストは境界値で固定済みのため kill される想定）。
  - `lib/chat.ts` `replaceWithHistory` の `reduce` 初期値 `''`（空履歴時のみ影響）。
  - `lib/viewer-stage.ts` の `setState('idle')` の早期 return 側 `undefined` 返却（React の effect クリーンアップ省略と等価）。
