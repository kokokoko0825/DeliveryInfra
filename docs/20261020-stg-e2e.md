# stg デプロイと実機 E2E 確認（2026-10-20）

stg に3スタックをデプロイし、Playwright で実際の画面を操作して、オンライン配信の主要な流れが動くことを確認した。
URL: https://d9fhvrzkwxgi4.cloudfront.net（CloudFront 無料プラン適用済み、Okta・SES なし）

## 確認できたこと

| 流れ | 結果 |
| --- | --- |
| 仮パスワードでログイン → 初回パスワード設定（12文字未満を拒否）→ 表示名（21文字を拒否） | OK |
| 管理者メニューとロール別の遷移、`/api/*` の OAC 経由の GET / PUT / POST（本文ハッシュ） | OK |
| コメント送信・受信・別タブへの即時削除反映・CSV 出力（BOM 付き） | OK |
| PDF のアップロード（presigned POST・`%PDF-` 検証）→ 視聴者の iframe 表示（スライド用 Cookie） | OK |
| スイッチャー起動 → 配信開始（確認ダイアログ）→ 視聴者が番組映像を受信 → 視聴者数表示 → 配信終了 → 視聴画面が自動で終了表示 | OK |
| 録画 → recording Lambda → 非公開アーカイブ登録（保存期限 +365日）→ 管理者の HLS 再生（アーカイブ用 Cookie、nodownload）→ 削除で S3 からも消える | OK |
| 配信前チェック（ステージ3つ IDLE、Chat ACTIVE）、ユーザー管理（自分の行は操作不可、最終ログイン記録） | OK |
| 認証なしの `/api/*` は 401、`/files/*` は 403、セキュリティヘッダー（CSP・HSTS 等） | OK |

## デプロイと E2E で見つけて直した不具合

| ID | 内容 | 修正 |
| --- | --- | --- |
| D-01 | IVS 録画設定・Chat ログ設定が先にバケットポリシーを書き込み、CDK のポリシー作成が失敗 | 依存関係でポリシーを先に作成。循環参照回避のため api は Chat Room / StorageConfiguration を名前で解決（94f79c1） |
| D-02 | stg のバケットに中身があるとロールバック時に DELETE_FAILED | stg は autoDeleteObjects（94f79c1） |
| D-03 | WAF の scope-down 付きレート制限が無料プランの対象外 | 全パスを 50,000件/5分で数える（206fd97） |
| D-04 | ESM バンドルで `Dynamic require of "node:https"` により全 Lambda が初期化失敗 | createRequire バナー、素の Node で読み込む結合テスト（40bf92b） |
| E2E-01 | 配信開始が AccessDenied（IVS が呼び出し元の権限で録画バケットを確認する） | api に録画バケット限定の `s3:GetBucketLocation`（a18f045） |
| E2E-02 | favicon が 403 | SVG favicon（a18f045） |
| E2E-03 | 「タップして音声オン」が番組映像に重なる | コントロールバーへ移動（a18f045） |
| E2E-04 | コメント審査が遅い（warm 531ms / cold 808ms + init） | 読み取り並列化・TransactWrite 1回・メモリ 1024MB → cold 256ms（a18f045） |

## 実機での確認が残っている項目

- カメラ・マイク・画面共有の送信（デバイスが必要）、6カメラ＋5マイクの同時送信、遅延1秒未満（仕様書 8.2 の PoC）
- 視聴画面を開いてから映像が出るまで 20〜30秒かかった（ヘッドレスブラウザの WebRTC 接続による可能性。実機で計測する）
- Okta 連携・SES 送信元（未設定）
- Cognito の WriteAttributes を空にしたとき、利用者による属性変更が拒否されること

テストで作ったユーザー・コメント・スライド・アーカイブ・録画は削除済み（DynamoDB は 0 件）。
