## 詳細

### R2-01 [Medium / 確実] 切断失敗時に旧送信枠も失われる

- 根拠: plan 3章の送信端末枠（45秒で失効し、枠再利用時に旧参加者を切断）、5章 API の端末上限、要件 F-CAM-06 / F-MIC-05。
- 実装: `PutCommand` は `ALL_OLD` で同じ枠の旧レコードを返しながら新しい枠レコードに置換する。その後 `DisconnectParticipant` が失敗すると `router.ts:158` は新しい `deviceId` の行を削除するだけで、置換前の行を戻さない。
- 失敗シナリオ: IVS の一時障害や権限エラーで旧参加者の切断が失敗する。旧参加者は接続を維持したまま DynamoDB の枠は空になるため、別端末が同じスロットを取得でき、同時送信数が仕様上限を超える可能性がある。
- 修正案: 切断完了前に旧枠を不可用状態として条件付き予約し、切断成功後に新枠へ確定する。切断失敗時に旧枠を条件付きで復元する場合は、競合で復元が新規取得を上書きしない条件も設ける。

### R2-02 [Medium / 確実] 招待時のグループ付与失敗でユーザーが孤立する

- 根拠: plan 5章 `POST /api/users/invite` と要件 F-USR-01。部分成功は許容されるが、失敗したアドレスを再処理できる必要がある。
- 実装: `AdminCreateUser` 成功後に `AdminAddUserToGroup` が失敗すると catch で `FAILED` として返すだけで、作成済み Cognito ユーザーを削除/補償しない。
- 失敗シナリオ: 招待先に仮パスワードメールが送られた後、グループ付与だけが失敗する。管理画面では失敗と表示され、再招待すると `UsernameExistsException` で `ALREADY_EXISTS` になる。ユーザーはロールなしのため API に入れず、管理者が手動修復するまで復旧できない。
- 修正案: グループ付与失敗時に作成ユーザーを削除して補償し、削除も失敗した場合は `CREATED_WITHOUT_ROLE` 等の修復可能な結果を返す。監査ログに補償失敗も残す。

### R2-03 [Medium / 確実] 配信終了 Chat イベントが再試行で復旧しない

- 根拠: plan 5章の `broadcast-ended` カスタムイベント、F-SW-09 / F-REC-02。リアルタイムで画面を同期する設計。
- 実装: recording ハンドラは DynamoDB の状態を `ended` に更新した後にイベントを送る。送信失敗で Lambda が失敗して再試行されると、次回は条件 `status=live` が成立せず `broadcastEnded=false` となり、イベント送信をスキップする。同じ順序で `/broadcast/stop` も状態更新後に SendEvent を呼び、失敗時にクライアントの再試行は `BROADCAST_NOT_LIVE` となる。
- 失敗シナリオ: IVS Chat が一時的に失敗したタイミングで配信終了イベントが起きる。DB は終了状態だが、視聴者/管理画面の Query invalidation は届かず、次のイベントや手動再読込まで表示が古いままになる。
- 修正案: 状態更新とイベント送信を再試行可能な Outbox 行に記録し、成功後に送信済みにする。最小修正なら ended 状態でもイベントを再送する冪等キー付き処理にし、重複イベントをクライアントが許容する。

### R2-04 [Low / 確実] 不正ロールのユーザーを viewer と誤表示する

- 根拠: plan 5章のロール決定規則（ロールなしは初回のみ refresh 要求、複数/不正ロールは拒否）と要件 F-USR-02 の管理ユーザー一覧。
- 実装: `listUsers` はグループがちょうど1つの有効ロールでない場合も `role: 'viewer'` を返す。認証時には同条件を `403 INVALID_ROLE` にしており、一覧表示だけが異なる。
- 失敗シナリオ: 管理者が Cognito に手動で複数グループを付けたユーザーを一覧で viewer と認識し、データ異常やログイン不能に気づかない。
- 修正案: 応答に `role: null` / `roleStatus: invalid` を加えて異常を明示し、管理画面で修復可能にする。ロールなしと複数所属を区別する。

### R2-05 [Low / 確実] スライダーのタップ領域が44pxに満たない

- 根拠: plan 6章の Apple HIG / タップ領域44px。`index.css` の44px指定は button / a / input / textarea / select に限定される。
- 実装: shadcn Slider の横ルートは高さ指定がなく、トラックは `h-1.5`、Thumb は `size-4`。スイッチャーの音量・トランジション操作はこの部品をそのまま使う。
- 失敗シナリオ: タッチ端末で細いトラック/16px Thumb を狙いにくく、音量や切替時間を誤操作する。キーボードフォーカスは実装されているため、問題は主にポインター操作領域。
- 修正案: Thumb の見た目を保ったまま Slider ルートに `min-h-11` を与えるか、十分な高さの透明な操作領域を設ける。
