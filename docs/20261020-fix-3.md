## R3-02 の規則（同じ端末名）

| 状況 | API の応答 | 画面 |
| --- | --- | --- |
| 他人が稼働中 | 409 `DEVICE_NAME_IN_USE`（`takeover` を付けても同じ） | 「CAM1 は他の端末が使用中です。別の端末名を選んでください。」 |
| 本人の別端末が稼働中 | 409 `DEVICE_NAME_IN_USE_SELF` | 「CAM1 はあなたの別の端末で送信中です…」＋「この端末に切り替える」 |
| 「切り替える」を押した | 200。旧端末を切断し、新しい枠に `replacedDeviceId` を記録 | 新端末で送信中 |
| 置き換えられた旧端末 | STAGE_LEFT `participant-disconnected`、またはハートビートで 409 `DEVICE_REPLACED` | 再接続せずに停止し「サーバーから切断されたため…」 |
| 自動再接続中に名前を取られていた | 409 `DEVICE_NAME_IN_USE(_SELF)` | 取り合わずに停止 |

例: カメラ担当がスマホでタブを開き直す → 旧タブの枠が最大45秒残るため `DEVICE_NAME_IN_USE_SELF` → 「この端末に切り替える」で即座に移る。旧タブが生きていても切断されて止まるので、交互に切断し合うループは起きない。

既知の制約: 自動再接続で旧枠の解放（DELETE）が回線断で失敗した場合、自分の旧枠が残って `DEVICE_NAME_IN_USE_SELF` になり停止する。その場合は「この端末に切り替える」で再開できる。
