# インフラ（AWS CDK）実装メモ

対象: `infra/`（AWS CDK v2 / TypeScript）、`scripts/cloudfront-keypair.sh`。
仕様: `docs/spec/requirements.md`（5・6・9章）、`plan/20261019-online-delivery.md`（3〜5章）。

## 1. 構成

環境は `-c env=stg|prod` で切り替え、同じ手順で2環境を作る（F-OPS-03）。スタック名は `delivery-<env>-*`。

| スタック | リージョン | 内容 |
| --- | --- | --- |
| `delivery-<env>-edge-waf` | us-east-1 | CloudFront 用 WebACL（スコープ CLOUDFRONT は us-east-1 のみ） |
| `delivery-<env>-main` | ap-northeast-1 | Cognito、DynamoDB、S3、IVS、IVS Chat、Lambda、CloudFront、CloudTrail、SPA 配置 |
| `delivery-<env>-pricing-plan` | us-east-1 | CloudFront フラットレート料金プラン（Free）のサブスクリプション |

依存の向き: edge-waf → main（WebACL ARN）→ pricing-plan（ディストリビューション ARN）。リージョンをまたぐ参照は CDK の `crossRegionReferences` を使う。

固定費のかかるサービス（ALB、NAT、VPC、コンテナ、Secrets Manager、Route 53、有料 WAF）は作らない（テストで不在を検証）。

### 主なリソース

- **Cognito**: 自己サインアップ不可、パスワード12文字以上・大小英字・数字、招待メール（`sesFromEmail` 指定時は SES、未指定は Cognito 既定）、グループ admin / camera / audio / presenter / viewer、Hosted UI のプレフィックスドメイン（既定 `delivery-<env>-<アカウントID>`）、機能プラン LITE。
  - App Client: シークレットなし、SRP、アクセス/ID トークン1時間、リフレッシュ12時間。
  - トリガー: `cognito` 関数を PostConfirmation と PostAuthentication の両方に設定。Okta ユーザーの初回サインインでは PostAuthentication は呼ばれず PostConfirmation（`PostConfirmation_ConfirmSignUp`）が呼ばれるため（AWS ドキュメント「Lambda triggers for federated users」）。
- **DynamoDB**: 単一テーブル `PK`/`SK`（String）、GSI なし（API は PK 単位の Query で設計する）、オンデマンド、TTL 属性 `ttl`、AWS 管理キー（aws/dynamodb）で暗号化。Stream（`OLD_IMAGE`）を有効化し、アーカイブ削除に使う（下記「アーカイブの期限削除」）。
- **S3**（全てパブリックブロック・SSE-S3・TLS 1.2 以上強制・所有者強制）

  | バケット | 用途 | ライフサイクル |
  | --- | --- | --- |
  | web | SPA | なし |
  | content | `slides/`、`comment-exports/`、IVS Chat ログ `AWSLogs/<アカウント>/IVSChatLogs/...` | `AWSLogs/` を365日で削除 |
  | recording | IVS コンポジット録画 `<stageId>/<sessionId>/<destId>/composite/...` | Intelligent-Tiering（0日目）のみ。期限での削除はしない（`archive-expiry` が消す） |
  | log | S3 アクセスログ `access-logs/`、CloudTrail `cloudtrail/` | 90日 / 365日 |

- **IVS Real-Time**: ステージ production / slide / broadcast、EncoderConfiguration（1280x720 / 30fps / 2.5Mbps）、StorageConfiguration（recording バケット）。全て CloudFormation のネイティブリソースで作れるため AwsCustomResource は不要。
- **IVS Chat**: ルーム1つ（最大200文字、審査 Lambda `chat-review`、失敗時 DENY）、LoggingConfiguration → content バケット。
- **Lambda**（nodejs22.x / arm64 / ログ90日）: `apps/api/dist/<dir>/index.mjs` の `handler` を使う。

  | 関数 | dist | 起動元 |
  | --- | --- | --- |
  | api | `api` | 関数URL（AuthType AWS_IAM）← CloudFront OAC |
  | chat-review | `chat-review` | IVS Chat のメッセージ審査 |
  | recording | `recording` | EventBridge `aws.ivs` / `IVS Composition State Change` |
  | cognito | `cognito-trigger` | Cognito PostConfirmation / PostAuthentication |
  | archive-expiry | `archive-expiry` | DynamoDB Stream（TTL によるアーカイブ行の削除だけ） |

  未ビルドなら「apps/api is not built」を投げるスタブで synth し、警告を出す（デプロイ前に `pnpm --filter api build`）。
- **CloudFront**（既定ドメイン `*.cloudfront.net`、WAF 関連付け、HTTP/2+3）

  | パス | オリジン | 設定 |
  | --- | --- | --- |
  | 既定 | web バケット（OAC） | CachingOptimized、viewer-request で SPA フォールバック |
  | `/api/*` | api 関数URL（OAC Lambda、常に署名） | CachingDisabled、AllViewerExceptHostHeader（`X-Auth-Token`・`x-amz-content-sha256` を含む全ヘッダー転送）、全メソッド、viewer-request で `x-forwarded-host` を上書き |
  | `/files/archives/*` | recording バケット（OAC） | trusted key group 必須、`/files/archives` を外して S3 キーへ |
  | `/files/slides/*` | content バケット（OAC、`/files/*` と同じオリジン） | trusted key group 必須、`/files` を外して S3 キーへ。同一オリジンからの iframe 埋め込みを許可 |
  | `/files/*` | content バケット（OAC） | trusted key group 必須、`/files` を外して S3 キーへ |

  全ビヘイビアの viewer-response で HSTS / CSP / X-Content-Type-Options / X-Frame-Options / Referrer-Policy / Permissions-Policy を付与する。
  埋め込みの可否はパスで分ける（R1-05、F-SLD-03）。U-02 はダイアログ内の iframe で `/files/slides/<id>.pdf` を表示するため、ここだけ同一オリジンを許可する。

  | パス | `X-Frame-Options` | CSP `frame-ancestors` | CloudFront Function |
  | --- | --- | --- | --- |
  | `/files/slides/*` | `SAMEORIGIN` | `'self'` | `SlideSecurityHeadersFunction` |
  | 上記以外（SPA・`/api/*`・`/files/archives/*`・`/files/*`） | `DENY` | `'none'` | `SecurityHeadersFunction` |

  例: SPA（`https://dxxxx.cloudfront.net/slides`）が `<iframe src="/files/slides/abc.pdf">` を開くと表示される。外部サイトが同じ URL を iframe に入れるとブラウザが拒否する。コメント CSV（`/files/comment-exports/...`）は `DENY` のまま。
- **WAF**: AWSManagedRulesCommonRuleSet、AWSManagedRulesKnownBadInputsRuleSet、AWSManagedRulesAmazonIpReputationList、IP ごとのレート制限（全パス、5分50,000件でブロック）の4ルール。根拠は3章「レート制限の上限」。
- **CloudTrail**: マルチリージョン証跡1本 → log バケット `cloudtrail/`（ログファイル検証あり）。
- **SPA 配置**: `apps/web/dist` を配置（ハッシュ付きアセットは1年キャッシュ、`index.html` と `config.json` は no-cache で配置後に無効化）。`config.json` は CDK が生成する。

  ```json
  { "region": "ap-northeast-1", "userPoolId": "ap-northeast-1_xxxx", "userPoolClientId": "xxxx",
    "oauth": { "domain": "delivery-stg-123456789012.auth.ap-northeast-1.amazoncognito.com",
               "redirectSignIn": "https://dxxxx.cloudfront.net/login",
               "redirectSignOut": "https://dxxxx.cloudfront.net/login", "oktaProviderName": "Okta" } }
  ```

  `oauth` は Okta 設定時のみ。Chat Room ARN など SPA に不要な値と秘密情報は入れない。
- **IAM（レビュー指摘での追加分）**: api に `ivs:ListStageSessions`（`/api/status`、R1-06）と `ivs:DisconnectParticipant`（失効した端末の切断、R1-07）を3ステージ限定で付与。`ivs:GetStage`・`ivschat:GetRoom` は既存。recording に `ivs:GetComposition`（`composition/*`、R1-21）。
- **Output**: CloudFrontDomain、DistributionId、UserPoolId、UserPoolClientId、CognitoDomain、TableName、各バケット名、ChatRoomArn、各 Stage ARN、CloudFrontKeyPairId、CloudFrontPrivateKeyParameter。

## 2. API との契約（Lambda 環境変数）

ハンドラごとに必要な変数だけを渡す。`AWS_REGION` は Lambda の予約変数なので設定しない（ランタイムが自動設定）。

| 関数 | 環境変数 |
| --- | --- |
| api | NODE_ENV, TABLE_NAME, USER_POOL_ID, USER_POOL_CLIENT_ID, STAGE_PRODUCTION_ARN, STAGE_SLIDE_ARN, STAGE_BROADCAST_ARN, CHAT_ROOM_NAME, CONTENT_BUCKET, RECORDING_BUCKET, RECORDING_STORAGE_CONFIGURATION_NAME, ENCODER_CONFIGURATION_ARN, CLOUDFRONT_KEY_PAIR_ID, CLOUDFRONT_PRIVATE_KEY_PARAMETER（Chat Room と StorageConfiguration は ARN でなく固定名。例: stg は `delivery-stg-room` / `delivery-stg-recording`） |
| chat-review | NODE_ENV, TABLE_NAME（ルーム ARN はイベントの RoomArn） |
| recording | NODE_ENV, TABLE_NAME, RECORDING_BUCKET, CHAT_ROOM_ARN, STAGE_BROADCAST_ARN |
| cognito | NODE_ENV, TABLE_NAME（User Pool ID はイベントの userPoolId） |
| archive-expiry | NODE_ENV, RECORDING_BUCKET（テーブルは読まない。削除前の値は Stream の OldImage にある） |

- api の `CHAT_ROOM_NAME` / `RECORDING_STORAGE_CONFIGURATION_NAME` は CDK の `name` と同じ文字列。apps/api が初回利用時に `ivschat:ListRooms` / `ivs:ListStorageConfigurations` で名前が完全一致する ARN を引き、モジュールスコープでキャッシュする（0件・複数件はエラー、`apps/api/src/resources.ts`）。List 系はリソースを絞れないため Resource `*`、それ以外の Room / StorageConfiguration 向けアクションは同アカウント・同リージョンの `room/*` / `storage-configuration/*` に限定する。
- `CLOUDFRONT_KEY_GROUP_ID` は API が使っていないため渡さない（R1-25）。`apps/api/src/env.ts` では optional なので、渡さなくても起動できる。

### アーカイブの期限削除（R1-22）

録画バケットのライフサイクルで一律に消すと、仕様 5.5 の「管理者が延長できる」を満たせず、DynamoDB のアーカイブ行だけが残る。そこで次の流れで消す。

1. API がアーカイブ行に `retainUntil`（初期は作成から365日、管理者が延長）と `ttl`（`retainUntil` の Unix 秒）を書く。
2. DynamoDB の TTL が期限切れの行を削除し、Stream（`OLD_IMAGE`）に `REMOVE` を流す。
3. イベントソースマッピングのフィルターで、次の条件をすべて満たすレコードだけを `archive-expiry` に渡す。
   - `eventName` が `REMOVE`
   - `userIdentity` が `{ type: "Service", principalId: "dynamodb.amazonaws.com" }`（TTL による削除。API の DeleteItem では付かない）
   - `OldImage.recordingPrefix`（String）がある（アーカイブ行。PK の形式に依存しない）
4. `archive-expiry` は `OldImage.recordingPrefix` 配下を `ListObjectsV2` → `DeleteObjects` で消す。

例: `retainUntil=2027-10-19T00:00:00Z` のアーカイブは `ttl=1823904000`。管理者が延長すると API が両方を書き換えるので、消えるのは延長後の期限（TTL は期限後数日以内に削除する）。

- 管理者の削除（`DELETE /api/archives/{id}`）は API が録画も消すので、Stream のフィルターで除外される。
- バッチ10件、失敗時は二分割（`bisectBatchOnError`）して最大5回再試行。ハンドラは `batchItemFailures` を返せる（`ReportBatchItemFailures`）。再試行を使い切ったレコードは捨てられ、録画が残る（アーカイブ行は消えているので再生はできず、残るのは保存料金のみ）。
- 権限: 録画バケットの `s3:ListBucket`（バケット）と `s3:DeleteObject`（オブジェクト）、Stream の読み取り（イベントソースが付与）のみ。

- `CLOUDFRONT_DOMAIN` は渡さない。API は `x-forwarded-host` ヘッダーを使う（CloudFront Function が閲覧者の Host で必ず上書きするため、クライアント送信値は届かない）。
- ファイルの URL: スライドは `https://<domain>/files/slides/<id>.pdf`、録画は `https://<domain>/files/archives/<recordingPrefix>/media/hls/multivariant.m3u8`。署名付きCookie はパス別に発行する（スライドは `/files/slides/*`、アーカイブは `/files/archives/<prefix>/*`。plan 5章、R1-08）。CloudFront 側はどちらも同じ trusted key group で検証する。
- 秘密鍵パラメータ名は `/delivery-<env>/cloudfront/private-key`。

### 循環参照を避けた箇所

| 循環 | 回避策 |
| --- | --- |
| api Lambda(env) → Distribution → 関数URL → api Lambda | `CLOUDFRONT_DOMAIN` を渡さず `x-forwarded-host` を使う |
| content バケット(CORS) → Distribution → バケット | Distribution 作成後に AwsCustomResource（PutBucketCors）で CloudFront ドメインだけを許可 |
| App Client(コールバックURL) → Distribution → api Lambda(env: Client ID) → App Client | Client は OAuth なしで作り、Okta 設定時のみ作成後に AwsCustomResource（UpdateUserPoolClient）で OAuth とコールバックを設定。設定値は `buildWebClientSettings` で共通化 |
| chat-review(env) ⇄ Room、cognito(env/IAM) ⇄ User Pool | 環境変数をハンドラ別にする。cognito の IAM は関数が依存しない別ポリシーで付与 |
| 録画/ログのバケットポリシー → Distribution → 関数URL → api Lambda(env/IAM) → StorageConfiguration / Chat Room(→ ChatLogging) → バケットポリシー | IVS は作成時にバケットポリシーへ書き込むため、StorageConfiguration / ChatLogging は CDK のバケットポリシーに明示依存させる（後から作るとポリシーが `The bucket policy already exists` で CREATE_FAILED）。代わりに api は両者の ARN を参照せず、固定名を環境変数で受け取り List API で解決する。IAM は `room/*` / `storage-configuration/*`。recording など Distribution に依存されない関数は ARN 参照のまま |

## 3. CloudFront 無料プランと WAF

### レート制限の上限（R1-13）

IP ごとのレート制限は全パスを数える。当初は `/api/*` だけを数える scope-down 付きにしていたが、stg 初回デプロイで CloudFront 無料プランのサブスクリプションが「web ACL is not eligible」で拒否されたため、条件なしに変更した（2026-10-20）。上限は1人あたり SPA 初回約45件 + API 33件 + アーカイブ HLS 約30件 = 108件、NAT 配下300人で 32,400件に約1.5倍の余裕を見て 50,000件/5分とする。以下の API 件数の内訳はその一部。

上限は「社内 NAT の出口 IP 1つの向こうに視聴者300人」を想定して決めた。

| 項目 | 件数（5分あたり・1人） | 根拠（apps/web） |
| --- | --- | --- |
| 視聴統計 `GET /api/broadcast/stats` | 20 | `WatchPage.tsx` 15秒ごと |
| 配信状態 `GET /api/broadcast` | 5 | `WatchPage.tsx` 60秒ごと |
| 入室時（me・broadcast・tokens・comments/recent・cookies など） | 約8 | 画面表示時に1回ずつ |

300人 ×（25 + 8）= 9,900件。再読込・再接続の余裕を約1.5倍見て **15,000件 / 5分**（`DEFAULT_RATE_LIMIT`）。送信端末（最大11台 × 15秒ハートビート = 220件）は誤差。1つの IP から 15,000件 / 5分（約50件/秒）を超える呼び出しはブロックされる。

AWS ドキュメント（CloudFront Developer Guide「CloudFront flat-rate pricing plans」、WAF Developer Guide「Using AWS WAF with CloudFront Flat-Rate Pricing Plans」、CloudFormation `AWS::PricingPlanManager::Subscription`）で確認した内容:

- 料金プランは1ディストリビューションごと。Free は月100万リクエスト・100GB、超過料金なし（超過が続くと速度調整の可能性）。Free プランは1アカウント3つまで（stg・prod で2つ）。
- プランには WAF の WebACL（1つ）が必須で、プラン中は関連付けを外せない。Free の WAF ルール上限は5（本構成は4）。AWS マネージドルールと IP ごとのレート制限は Free で使える。独自の「ルールグループ」と Bot Control 等は不可。
- Free で**使えない**もの: カスタムのキャッシュポリシー / オリジンリクエストポリシー / レスポンスヘッダーポリシー（Business 以上）、アクセスログ（Pro 以上）、リアルタイムログ、OAI など。キャッシュビヘイビアは5つまで（本構成は5）。
  - 本構成のキャッシュビヘイビアは既定 + `/api/*`・`/files/archives/*`・`/files/slides/*`・`/files/*` の5つで上限ちょうど。これ以上パスを分けられない。
  - このため、マネージドポリシー（CachingOptimized / CachingDisabled / AllViewerExceptHostHeader）だけを使い、セキュリティヘッダー（CSP 含む）は CloudFront Functions（Free で利用可）で付与する。
  - SPA の 403/404 → index.html はディストリビューション全体に効くエラーページ置換を使わず、既定ビヘイビアの viewer-request 関数で拡張子のないパスを書き換える（`/api` と `/files` には影響しない）。
- AWS Free Tier を利用中のアカウントはプランに加入できない。
- CDK でできること: WebACL（us-east-1 スタック）、ディストリビューションへの関連付け、`AWS::PricingPlanManager::Subscription`（PlanTier FREE、us-east-1 スタック）。Free は作成時に即有効になる。
- 手動で行うこと:
  1. 初回デプロイ後、CloudFront コンソールの対象ディストリビューションで「Pricing plan: Free」になっていることを確認する。サブスクリプション作成が失敗した場合（アカウント条件など）は `-c cloudFrontFreePlan=false` でデプロイし、コンソールの「Manage plan」から Free を選ぶ。
  2. 月1回、コンソールで使用量（リクエスト数・転送量）を確認する（5.2）。
  3. プランの変更・解約はコンソールで行う（CloudFormation ではプラン階層を変更できない）。

## 4. デプロイ手順（stg の例。prod は `env=prod`）

```sh
# 0. 前提: AWS 認証済み。両リージョンを bootstrap（初回のみ）
npx cdk bootstrap aws://<ACCOUNT>/ap-northeast-1 aws://<ACCOUNT>/us-east-1

# 1. CloudFront 署名鍵（初回とローテーション時）
scripts/cloudfront-keypair.sh stg        # 秘密鍵→SSM SecureString、公開鍵→infra/keys/stg-cloudfront-public.pem（コミットする）

# 2. 任意設定（非秘密）を infra/.env.stg に書く（infra/.env.example 参照）
#    SES を使う場合: SES で送信元アドレス/ドメインを検証し、本番アクセス（サンドボックス解除）を申請しておく
#    Okta を使う場合: client secret を SSM に登録（値をシェル履歴に残さない）
read -rs OKTA_SECRET && aws ssm put-parameter --region ap-northeast-1 --type SecureString \
  --name /delivery-stg/okta/client-secret --value "$OKTA_SECRET" && unset OKTA_SECRET
#    Okta 側のリダイレクト URI: https://<CognitoDomain>/oauth2/idpresponse

# 3. ビルドとデプロイ（3スタックを依存順に）
pnpm --filter api build && pnpm --filter web build
cd infra && npx cdk deploy --all -c env=stg
```

- 同一アカウントに stg と prod を置く場合、2本目の CloudTrail 証跡は有料なので片方を `-c cloudTrail=false` にする。
- Okta の client secret をローテーションしたら、`aws cognito-idp update-identity-provider` で更新するか、IdP のプロパティを変えて再デプロイする（カスタムリソースはプロパティ変更時にのみ再実行される）。
- prod はデータ（DynamoDB・User Pool・S3）を RETAIN・削除保護あり。stg は削除される。

### 確認

```sh
npx cdk synth -c env=stg            # AWS 認証なしで synth できる（未ビルド・鍵未登録は警告のみ）
aws s3api get-bucket-policy --bucket <RecordingBucket>   # IvsCompositeWrite が残っていること
aws s3api get-bucket-cors --bucket <ContentBucket>       # AllowedOrigins が https://<CloudFrontDomain> のみ
```

## 5. 注意点・既知の制約

- **TLS 1.2 以上の強制**: 既定の `*.cloudfront.net` 証明書ではセキュリティポリシーが TLSv1 に固定され変更できない（CloudFront Developer Guide「Security policy」）。対応ブラウザ（5.4: 各最新版）は TLS 1.0/1.1 を無効化済みのため実際の接続は TLS 1.2 以上になる。S3 オリジン側は `s3:TlsVersion < 1.2` を拒否。厳密に強制するには独自ドメイン＋ACM 証明書（9.3）で `TLSv1.2_2021` を設定する。
- **IVS が書き換えるバケットポリシー**: StorageConfiguration（録画）と Chat の LoggingConfiguration は作成時に S3 バケットポリシーへ許可を追加する。CloudFormation がポリシーを更新すると消えるため、同等の許可（`ivs-composite.<region>.amazonaws.com` の PutObject、`delivery.logs.amazonaws.com` の PutObject/GetBucketAcl）をテンプレートにも入れてある。初回デプロイ後に実際のポリシーと比較し、差異があればテンプレートに合わせること。
- **署名鍵未登録時**: 破棄済み秘密鍵の公開鍵（`infra/src/keys.ts`）を使うフェイルクローズ。`/files/*` は誰も閲覧できない。
- **TypeScript 設定**: CDK の型が `exactOptionalPropertyTypes` と両立しないため infra だけ無効化。CDK アプリは Node の型除去（`--experimental-strip-types`）で実行するため、enum・パラメータプロパティなどは使わない（`erasableSyntaxOnly`）。

## 6. テスト
