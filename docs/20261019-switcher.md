## 2. 主な設計判断

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| ステージ識別 | `tokens[].stage` の論理名（production/slide/broadcast）で選ぶ。配列順に依存しない | coordinator 回答（shared commit 4f18af6） |
| カメラのソース ID | `camera:<端末名>` | 再接続で participantId が変わっても番組の画が保たれる。例: CAM1 が回線断から戻ると、PGM に出ていた CAM1 がそのまま映る |
| 合成タイマー | Worker 内 `setInterval`（30fps）→ Canvas → `captureStream(30)` | `requestAnimationFrame` / `requestVideoFrameCallback` は背面タブで止まるため |
| 映像途絶判定 | 500ms ごとに `getVideoPlaybackQuality().totalVideoFrames` の増加を確認し、2秒増えなければ「映像途絶」 | 同上。rVFC に頼らない |
| 音声 | 各チャンネル → Gain → マスター → `MediaStreamDestination`。ゲインは音量 0〜100 の2乗（例: 80 → 0.64） | 聴感に近い。カメラ切替と独立（F-SW-07） |
| 受信音声 | ミュートした `<audio>` にも接続 | Chrome は受信 WebRTC 音声を media 要素に繋がないと WebAudio に流れない |
| 配信開始順 | 配信用ステージへ PUBLISH → `POST /broadcast/start` | 録画開始時点で番組映像が届いているように。API 失敗時は送信を止める |
| スイッチャーのトークン | `purpose=switcher` の1回の応答に入る production/slide/broadcast の3本を各ステージで1回ずつ使う。同じステージが再接続するとき、または期限まで60秒を切ったときだけ取り直す（`createSwitcherTokens`） | switcher は端末枠を使わない（Review-1 R1-02）。トークンは10分で失効するので、起動から10分後の配信開始では取り直しになる |
| 送信側の再接続 | 前の deviceId の DELETE 完了を待ってから再発行（R1-17）。再接続中の 409 はバックオフで再試行 | 失効（45秒）待ちで上限に当たらないように。初回の 409 は再試行せず表示（F-CAM-06） |
| ハートビート 404 | 枠が失効したとみなし再接続 | 端末レコードが TTL で消えたケース |
| 同じ端末名の扱い（R3-02） | **後発が明示的に引き継いだときだけ置き換える。** 他人の稼働中の名前 → 409 `DEVICE_NAME_IN_USE`。本人の別端末の名前 → 409 `DEVICE_NAME_IN_USE_SELF`（画面に「この端末に切り替える」）。押すと `takeover: true` で取得し、旧端末を切断して枠に `replacedDeviceId` を残す。旧端末は STAGE_LEFT `participant-disconnected` か、ハートビートの 409 `DEVICE_REPLACED` で送信を止め、再接続しない。再接続（自動）では takeover を付けず、名前を取られていたら止める | 暗黙の置き換えだと、同名の2端末がハートビートのたびに互いを切断し合う。例: スマホでタブを開き直した → 旧タブの枠が45秒残るので「切り替える」を押すと即座に移れる |
| 端末名の初期値（R3-01） | `GET /api/devices/names?purpose=camera\|mic` で他人が使用中の名前を取り、最初の空き（例: CAM1・CAM2 使用中 → CAM3）を初期表示。取得失敗時は先頭 | 全員が初期値の CAM1/MIC1 のまま始めて衝突するのを防ぐ |
| 番組送信の再開（R3-04） | 配信中に開き直したときの再開（`startPublishing({ resume: true })`）は失敗しても送信をやめず、managed session のバックオフ再接続に任せる。成功時に送信中へ | 一瞬の回線不調で番組が止まったままにならないように |
| 再描画（R3-10） | レベルメーターは MixerPanel 内で 100ms ごとに `readLevels()` を読む。健全性は変化した時だけ state 更新。コメント欄は `memo` で切り離す | 合成と同じメインスレッドを画面全体の 10Hz 再描画で消費しない |
| トランジション | カット=即時に PVW/PGM 入れ替え。ディゾルブ=smoothstep の不透明度、ワイプ=左→右の切り抜き。0.3〜2秒（0.1刻み）。トランジション中に選び直したプレビュー（PiP 含む）は完了後も保持し、選び直していなければ直前の番組がプレビューに戻る（R3-06） | F-SW-03/04 |
| PiP | サブは 16:9、幅 小25%/中33%/大40%、余白は幅の2.5%。例: 中・右下 = (826, 451, 422×237) | F-SW-05 |
| ショートカット | 1〜6 カメラ、7 スライド、8 待機画面、Space カット、Enter トランジション。入力欄では無効、ボタン・リンク・`<summary>` 上では Space/Enter のみ無効（フォーカス要素の内側からは `closest` で判定。R3-05） | マウス操作でボタンにフォーカスを移さない（`onMouseDown` で preventDefault）ので、クリック後も Space でカットできる |

## 5. ミューテーションテスト

- 設定: `apps/web/stryker.media.config.json`（対象: `switcher/engine`, `sender/engine`, `lib/ivs` のロジック、`switcher/media`（compositor・audioGraph・videoRegistry・frameClock。Worker 本体は除く）、再生部品 `archives/HlsPlayer.tsx`・`viewer/VideoPlayer.tsx`（R3-12）。break 80）
- **スコア: 未計測。** この作業環境のサンドボックスがローカルポートの listen を禁止しており、Stryker がログサーバー起動時に `listen EPERM: operation not permitted 0.0.0.0` で終了するため。coordinator 判断で後続タスクで計測する。
- 実行コマンド: `cd apps/web && pnpm exec stryker run stryker.media.config.json`（レポートは `reports/mutation/media.html` / `media.json`）
- 計測時に生き残りやすいと見込む箇所（等価変異の候補。計測後に確定させること）:
  - `layout.ts` `fitRect` の `sourceRatio === targetRatio` 早期 return: 削除しても contain/cover どちらの分岐でも同じ矩形になるため等価
  - `transition.ts` `ease` 内の clamp: 呼び出し元の `transitionProgress` が既に 0〜1 に収めているため、合成経路からは区別できない（単体テストで -1 / 2 を与えて検出はしている）
  - `mixer.ts` `gainOf` の音量 clamp: reducer が範囲外を拒否するため通常経路では到達しない（単体テストで 150 / -10 を与えて検出はしている）
  - `stage.ts` の `config ?? {}`: SDK モックは config を保持するだけなので `{}` と `undefined` の差は検証できるが、実 SDK の挙動差は無い
  - `reconnect.ts` `realScheduler`: タイマー差し替えのため、`clearTimeout` の型キャストのみの変異は等価

## 6. 既知の制約・残課題

- 実機確認（iOS Safari のカメラ切替、Windows Chrome のシステム音声共有、管理者 PC での 6 カメラ + スライド合成の処理落ち、遅延 1 秒未満）は PoC（8.2）で行う
- `pagehide` 時の枠解放は best effort（非同期で SHA-256 を計算するため届かない場合がある）。届かなくても 45 秒で失効する
- 番組映像の黒背景・既定待機画面の白文字は映像コンテンツの色で、UI のデザイントークンではない
