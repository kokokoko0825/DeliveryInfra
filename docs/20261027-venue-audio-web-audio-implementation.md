# 会場拡声・配信音声分岐の実装

作成日: 2026-10-27
根拠: [設計提案](./20261027-venue-audio-web-audio-design-proposal.md)

## 実装した経路

マイク送信画面は物理マイクを1回取得し、AEC・NS・AGCの無効化を要求する。取得したトラックを単一の Web Audio 入力ノードに接続する。会場側は既存の AudioWorklet に直接分岐して、10 ms単位の PCM を STUN による直接接続の DataChannel で送る。配信側は80 Hzのハイパスと軽いコンプレッサーを通し、Web Audio の出力トラックを既存 IVS Stage に送る。

会場送信スイッチはマイクごとに独立している。会場送信を止めても配信は続く。共通ミュートは物理入力トラックと IVS のミュート状態に適用する。Web Audio の準備に失敗した場合は画面にエラーを出し、配信用 DSP の構築に失敗した場合は配信側だけバイパスする。物理マイクのトラックが終了した場合は両経路を閉じる。

## 操作例

同じ試験名を端末の URL に付ける。例えばマイク端末は `/send/mic?trialId=room_42`、スピーカー端末は `/venue/speaker?trialId=room_42` を開く。マイク画面で「会場スピーカーにも送信」をオンにし、必要なら「送信開始」で配信も開始する。スピーカー端末は消音モードを解除し、音量ボタンで会場に合う音量にする。

会場セッションの計測値は各端末のブラウザに保存する。試験後に**マイクとスピーカーの両方**から CSV / JSON を出力する。`trialId` は端末をまたいで照合するための識別子であり、音響遅延の測定値ではない。RTTやパケット統計だけで「音が届いた」「目標遅延を満たした」と判定しない。

## 異常時と制約

- 会場接続の登録が失効したら会場送信を停止状態に戻し、計測記録を閉じる。配信は継続する。
- IVS のトークン取得中に送信を止めた場合、後から返ったトークンで接続しない。取得済みの端末枠は返却する。
- `getSettings()` に AEC・NS・AGC の値がなければ「確認できません」と表示し、推測で無効と判定しない。端末・OS側の固定処理もありうる。
- DSP は初期設定であり、従来のブラウザ標準 AEC・NS・AGC と同等の音質は保証しない。会場スピーカーの音をマイクが拾う配置では、エコーやハウリングを実機で確認する。
- 実機の音響遅延、配信映像との同期、音質、長時間運転、最大3マイク・5スピーカーは未検証である。これらを確認するまでは本番利用可能と判定しない。

- `pnpm --filter web lint`: 成功。
- `pnpm --filter web typecheck`: 成功。
